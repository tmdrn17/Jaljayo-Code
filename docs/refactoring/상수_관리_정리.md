# 상수 관리 정리

2차 리팩터링이 끝난 뒤 상수를 다시 점검하고, 공용 static 클래스로 옮기지 못한 곳을 반영한 기록입니다. 놓쳤던 조정 값 상수도 함께 정리합니다.

---

## 1. 무엇을 놓쳤나

### 1.1. 규칙이 원래 의도보다 좁았음

- 원래 의도는 **상수를 공용 static 클래스로 관리하는 것**이었습니다.
- 2차 계획(R1)과 `style.md` 5절에는 "**두 파일 이상이 쓰는 상수만** `SceneNames`/`Tags`로, 한 파일만 쓰는 상수는 그 클래스 위 `const`로"라는 제한이 들어갔습니다.
- 이 제한은 계획 안에 묻혀 있었고, 따로 확인받지 않았습니다. 그래서 `Player`처럼 자기만 쓰는 태그 10개를 클래스 안에 가진 파일이 그대로 남았습니다.

### 1.2. 계획에 적은 것도 빠졌음

- R1에는 `Invelope`, `JukeBox`, `FloorClearTrigger`, `MainHallDoor`, `StageClear`, `Fade`, `DoorController`를 `Tags.Player`로 바꾼다고 적었습니다.
- 하지만 이 7개 파일은 T1~T7 어느 세션에도 배정되지 않았습니다. 그래서 각 파일이 `PlayerTag = "Player"`를 따로 가진 채로 남았습니다.
- 같은 이유로 두 파일이 쓰는 `"UIManager"`(Player, Drag), 다섯 곳에 흩어진 입력 버튼 `"Interaction"`도 그대로였습니다.

## 2. 어떤 상수를 어디에 두나

| 종류 | 둘 곳 | 이유 |
|---|---|---|
| 태그 | `Core/Tags` (한 파일만 써도) | 태그는 Tag Manager에 프로젝트 전체로 등록되는 값입니다. 한 곳만 보면 코드가 쓰는 태그가 다 보이고, 새 태그가 기존 것과 겹치는지 바로 확인됩니다. |
| 씬 이름 | `Core/SceneNames` (한 파일만 써도) | 빌드 설정과 맞춰 볼 때 한 곳만 보면 됩니다. 빌드에 없는 씬은 주석으로 구분합니다. |
| Input Manager 축·버튼 | `Core/InputNames` (새로 만듦) | `InputManager.asset`에 프로젝트 전체로 등록되는 값입니다. |
| 씬 오브젝트 이름 (`GameObject.Find`, `name ==`) | 두 파일 이상이면 `Core/ObjectNames` (새로 만듦), 한 파일이면 그 클래스 | 특정 씬의 특정 오브젝트 이름이라, 찾는 클래스 옆에 있어야 읽기 쉽습니다. 여러 파일이 쓰면 값이 어긋나지 않게 한 곳에 둡니다. |
| 애니메이터 해시 | 그 Animator를 쓰는 클래스 | 오브젝트마다 다른 Animator Controller에 딸린 값입니다. |
| 화면 글자 (`Correct!`, 점수 앞 글자) | 그 클래스 | 그 UI만의 표시 값입니다. |
| 조정 값 (속도, 힘, 지연 시간) | `[SerializeField]` | 에디터에서 바꿀 수 있어야 하므로 상수로 두지 않습니다 (`style.md` 5절). |

**공용 클래스로 옮길 때의 이점과 비용**
- **이점:** 값이 한 곳에만 있어 오타나 값 불일치가 생기지 않습니다. 이름을 바꿀 때 한 곳만 고치면 됩니다. 프로젝트 전체 값(태그, 씬, 입력)을 한눈에 볼 수 있습니다.
- **비용:** 한 파일만 쓰는 값이면 읽을 때 다른 파일을 열어야 합니다. 공용 파일이 커지고, 여러 사람이 같은 파일에 줄을 추가해 충돌이 날 수 있습니다.
- 그래서 **프로젝트 전체에 등록되는 이름**(태그, 씬, 입력)은 모두 옮기고, **씬 오브젝트 이름**은 여러 파일이 쓸 때만 옮겼습니다.

## 3. 바꾼 것

### 3.1. 공용 클래스 (`Assets/02.Scripts/Core/`)

| 파일 | 변경 |
|---|---|
| `Tags.cs` | 5개 → 23개. 각 클래스에 흩어져 있던 태그 18개를 옮김 (`Statue`, `Water`, `Ground`, `Boss`, `Floor`, `SideSpike`, `Destination`, `SpawnPoint`, `Image`, `RightButton`, `Wall_D` 등) |
| `SceneNames.cs` | 빌드 밖 씬 9개 추가 (`MainHall`, `TestScene`, `StageFail`, `StageSelect`, `Stage1`~`Stage5`). 빌드 씬과 주석으로 구분 |
| `InputNames.cs` (새 파일) | `Horizontal`, `Vertical`, `Mouse X`, `Mouse Y`, `Jump`, `Interaction`, `Submit`, `Cancel` |
| `ObjectNames.cs` (새 파일) | `Player`(이름 비교), `UIManager`(`GameObject.Find`) |

### 3.2. 각 스크립트 (23개)

| 바꾼 내용 | 파일 |
|---|---|
| 지역 태그 const → `Tags.*` | Player, Bullet, FindPicture, GameManager, Spike, Wall, (LJW) Drag |
| `PlayerTag` → `Tags.Player` (R1에서 빠졌던 7개) | FloorClearTrigger, StageClear, Invelope, JukeBox, MainHallDoor, (LJW) DoorController, (LJW) Fade |
| 입력 이름 → `InputNames.*` | Player, CameraArm, GameManager, OXQuiz, JukeBox, MainHallDoor, Altar, (LJW) DoorController |
| 씬 이름 const → `SceneNames.*` | CountDown, SceneChanger, StageSelect |
| 오브젝트 이름 → `ObjectNames.*` | Player, (LJW) Drag (`UIManager`), FallingPlatform, WallSpawnTrigger (`Player` 이름 비교) |
| 문자열 그대로 쓰던 `GameObject.Find("Boss")` → 지역 const `BossName` | (LJW) BossHealth |

**이전 (Player)**
```csharp
    #region 상수
    private const string StatueTag = "Statue";
    private const string AnswerAreaTag = "AnswerArea";
    // ... 태그 10개
    private const string UIManagerName = "UIManager";
    // ...
        haxis = Input.GetAxisRaw("Horizontal");
        isInteractDown = Input.GetButtonDown("Interaction");
```
**이후 (Player)**
```csharp
    #region 상수
    // 이 클래스만 찾는 씬 오브젝트 이름. 태그·입력 이름은 Core의 Tags·InputNames에 있다.
    private const string GateOpenLeverName = "GateOpenLaber";
    // ...
        if (other.CompareTag(Tags.Statue)) NearObj = null;
        haxis = Input.GetAxisRaw(InputNames.Horizontal);
        isInteractDown = Input.GetButtonDown(InputNames.Interaction);
```

- 문자열 값은 하나도 바꾸지 않았습니다. 씬·프리팹 수정은 없습니다.
- `style.md` 5절 "매직 문자열" 규칙을 2절의 기준으로 고쳤습니다.

### 3.3. 확인

- `dotnet build Assembly-CSharp.csproj`: **오류 0개** (경고 141개는 기존과 같은 `CS0649` 계열)
- 남은 문자열 리터럴 검사 (`GetAxis("`, `GetButton("`, `CompareTag("`, `LoadScene("`, `WithTag("`): 0건
- 지역 태그·씬·입력 const 검사: 0건
- Unity 에디터 콘솔 확인은 아직 하지 않았습니다.

## 4. 조정 값 const → `[SerializeField]` (2차 R9에서 빠졌던 것)

`style.md` 5절은 에디터에서 바꿀 수 있어야 하는 값(속도, 힘, 지연 시간, 목표 개수 등)을 `const`로 두지 않게 정합니다. 2차 R9는 세션 담당 파일만 바꿔서, 아래 7개 파일이 남아 있었습니다.

| 파일 | 이전 (`const`) | 이후 (`[SerializeField]`, 같은 기본값) |
|---|---|---|
| (LJW) `WindPanel` | `FanSpeed`, `LiftImpulse`, `FallLiftImpulse` | `fanSpeed = 2000`, `liftImpulse = 0.6`, `fallLiftImpulse = 0.1` |
| (LJW) `MovePanel` | `PanelSpeed`, `DoorRotateSpeed` | `panelSpeed = 2.5`, `doorRotateSpeed = 100` |
| (LJW) `BossHealth` | `ShowBarDelay`, `HideBarDelay`, `LerpSpeed` | `showBarDelay = 2`, `hideBarDelay = 2.5`, `lerpSpeed = 10` |
| (LJW) `RotatingLog` | `SlideMaxZ`, `SlideMinZ`, `SlideSpeed`, `OrbitCenter` | `slideMaxZ = 43`, `slideMinZ = 39`, `slideSpeed = 0.6`, `orbitCenter = (0, 2.7, 58)` |
| (LJW) `KeyBoard` | `ShowDelay`, `KeyShowDuration`, `KeyInterval` | `showDelay = 3`, `keyShowDuration = 0.2`, `keyInterval = 0.25` |
| (LJW) `DoorController` | `ColliderOnDelay` | `colliderOnDelay = 1` |
| (LJW) `Stage2UI` | `ItemMissionCount`, `DragMissionCount` | `itemMissionCount = 5`, `dragMissionCount = 2` |

- 씬에 키가 없으므로 Unity가 필드 기본값을 씁니다. 지금 동작과 같습니다.
- `OXQuiz`의 `ClearAnswerCount = 10`은 문제 배열 길이를 베낀 값이라 `quizItems.Length`로 바꿨습니다 (`O_XQuiz.prefab`의 `quizItems`는 10개).

**const로 남긴 것 (style.md 5절 "const로 두는 것")**
- `CoinManager.MaxCoinCount`: 저장 배열 길이. 씬보다 먼저 static 배열을 만들어야 함
- `FindPicture.WrongKind`·`RightKind`: OnClick 정수 인자
- `VolumeControl.MuteVolume`: 오디오 믹서 최솟값
- `GameManager.MenuScenes`·`CursorVisibleScenes`: 씬 이름 묶음
- `LampDropAttack.LampRotation`: 전등 프리팹이 놓이는 고정 회전값

## 6. 남은 것

- **한 파일만 쓰는 오브젝트 이름:** `Player`의 `Npc3`·`Altar` 등, `ColorBox`·`FindPicture`·`Stage2UI`·`MovePanel`·`Cube`·`MoveFloor`·`BossHealth`의 이름 const는 기준대로 각 클래스에 두었습니다. 대부분 `GameObject.Find`에 쓰이며, `GameObject.Find`를 인스펙터 연결로 바꾸면 함께 없어집니다.
- **`RotatingLog`의 종류별 회전 속도:** `Spin(150f)`처럼 `switch` 안에 숫자로 적혀 있습니다. 종류(`LogKind`)마다 값이 달라 필드 하나로 옮길 수 없어 그대로 두었습니다.
